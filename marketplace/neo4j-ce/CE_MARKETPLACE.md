# Neo4j Community Edition - Azure Marketplace Publishing Guide

This document captures all details needed to publish Neo4j Community Edition on the Azure Marketplace. The CE listing requires **two separate offers** in Partner Center, following the same pattern as the existing Enterprise Edition.

## Overview: Two Offers Required

| | Enterprise Edition (existing) | Community Edition (new) |
|---|---|---|
| **Offer Type** | Azure Application (Solution Template) | Azure Application (Solution Template) |
| **Offer ID** | `neo4j-ee` | `neo4j-ce` |
| **Plan ID** | `byol` | `per-core-hour` |
| **Plan Name** | `byol` | `Per Core Hour` |
| **Pricing** | Bring Your Own License | $0.04/core hour |

| | Enterprise Edition VM (existing) | Community Edition VM (new) |
|---|---|---|
| **Offer Type** | Azure Virtual Machine | Azure Virtual Machine |
| **Offer ID** | `neo4j-ee-vm` | `neo4j-ce-vm` |
| **Offer Alias** | *(existing)* | `Neo4j Community Edition VM` |
| **Plan ID** | `byol` | `per-core-hour` |
| **Purpose** | VM image + billing meter | VM image + $0.04/core hour meter |

> **WARNING:** Offer IDs, Plan IDs, and names are **immutable** in Azure Marketplace. They appear in URLs and CLI commands. They cannot be changed or deleted after creation.

## Offer 1: `neo4j-ce` (Azure Application - Solution Template)

**Status:** Already created in Partner Center.

This is the Bicep/ARM template that orchestrates the full deployment (VNet, NSG, VM, disk, etc.). The code lives in `marketplace/neo4j-ce/`.

### Plan Configuration

- **Plan ID:** `per-core-hour`
- **Plan Name:** `Per Core Hour`
- **Plan Type:** Solution Template

### Technical Configuration

- **Version:** Start at `1.0.0`
- **Package file:** `archive.zip` (generated by `marketplace/neo4j-ce/makeArchive.sh`)
- Contains `mainTemplate.json` + `createUiDefinition.json`

### Logo

- **Large (350x350):** `logos/logo-mark-fullcolor-350x350.png` (Neo4j icon mark, full color, white background)
- Additional sizes may be needed — generate from `logos/logo-mark-fullcolor-RGB-whiteBG/logo-mark-fullcolor-RGB-transBG.png` (2100x2000 source)

### Key Differences from EE Template

| Aspect | Enterprise (`neo4j-enterprise`) | Community (`neo4j-ce`) |
|---|---|---|
| **Architecture** | VMSS (scale set, 1-10 nodes) | Single VM (standalone only) |
| **Modules** | network, identity, loadbalancer, vmss | network, disk, vm |
| **Node Count** | 1, 3-10 | 1 (standalone only) |
| **License Type** | Enterprise / Evaluation | Community (no license param) |
| **Neo4j Versions** | `5` | `latest`, `5` |
| **Image Reference** | `neo4j/neo4j-ee-vm/byol` | Currently `RedHat/RHEL/9-lvm-gen2` — **must change** to `neo4j/neo4j-ce-vm/per-core-hour` |
| **Cloud-init** | `scripts/neo4j-enterprise/cloud-init/` | `scripts/neo4j-ce/cloud-init/` |
| **Package installed** | `neo4j-enterprise` | `neo4j` |
| **Plugins** | APOC, GDS, Bloom | APOC only |

### Required Template Change Before Publishing

The CE template (`marketplace/neo4j-ce/modules/vm.bicep`) currently uses a stock RHEL image:

```bicep
imageReference: {
  publisher: 'RedHat'
  offer: 'RHEL'
  sku: '9-lvm-gen2'
  version: 'latest'
}
```

This must be updated to reference the published CE VM offer (once created):

```bicep
plan: {
  publisher: 'neo4j'
  product: 'neo4j-ce-vm'
  name: 'per-core-hour'
}
// ...
imageReference: {
  publisher: 'neo4j'
  offer: 'neo4j-ce-vm'
  sku: 'per-core-hour'
  version: 'latest'
}
```

**Status:** Needs to be created in Partner Center.

3. **Offer alias:** `Neo4j Community Edition VM`

### Plan Configuration

- **Plan ID:** `per-core-hour`
- **Plan Name:** `Per Core Hour`
- **Pricing:** $0.04/core hour (metered)

### Technical Configuration (Mirror EE Settings)

**Image type:**
- x64 Gen 2
- SKU ID: `per-core-hour`

**Operating system:**
- Family: Linux
- Vendor: Red Hat Enterprise Linux

**Open ports:**

| Bolt | 7687 | TCP |
| Browser HTTP | 7474 | TCP |
| Browser HTTPS | 7473 | TCP |

**Properties (check these):**
- [x] Supports VM extensions

**Recommended VM sizes:** Select 2 (matching EE pattern)

### VM Image: Creating the Image

The EE VM offer uses SAS URIs to VHDs in blob storage. The CE offer follows Microsoft's current best practice of using **Azure Compute Gallery** instead.

> **Reference:** [Create a VM offer from an approved base](https://learn.microsoft.com/en-us/partner-center/marketplace-offers/azure-vm-use-approved-base)

**Important finding:** The EE VHD is a base RHEL image — Neo4j is **not baked in**. It is installed at deploy time via cloud-init (`dnf install -y neo4j-enterprise`). The CE cloud-init does the same with `dnf install -y neo4j`. The CE image is also a base RHEL image with no Neo4j pre-installed.

#### Creating the CE Image with `makeVm.sh`

The `makeVm.sh` script automates the entire image creation process using Azure Compute Gallery.

**Prerequisites:**
- Azure CLI logged in (`az login`) with sufficient permissions (Owner or Contributor + User Access Administrator)

**Usage:**
```bash
cd marketplace/neo4j-ce
./makeVm.sh [resource-group] [region]
```

**Examples:**
```bash
# Use all defaults (resource group: neo4j-ce-image-rg, region: eastus2)
./makeVm.sh

# Specify all options
./makeVm.sh my-image-rg westus2
```

The script is **idempotent** — safe to re-run after a failure. It checks for existing resources and cleans up leftovers from previous runs.

**What it does:**

| Step | Action |
|---|---|
| 1 | Checks if resource group exists, creates if missing |
| 2 | Cleans up any leftover VM from a previous run, then creates a VM from the approved RHEL 9 Gen2 base image |
| 3 | SSHs in to install latest OS updates (marketplace certification requirement) and deprovision |
| 4 | Deallocates and generalizes the VM |
| 5 | Checks if Azure Compute Gallery (`neo4jmarketplace`) and image definition exist, creates if missing |
| 6 | Deletes any existing image version from a previous run, then captures the VM as image version `1.0.0` |
| 7 | Registers `Microsoft.PartnerCenterIngestion` provider and grants Partner Center access to the gallery |

**Deprovisioning** follows the [Microsoft best practices](https://learn.microsoft.com/en-us/azure/virtual-machines/linux/create-upload-generic):
```bash
sudo rm -f /var/log/waagent.log
sudo cloud-init clean --logs --seed
sudo waagent -deprovision+user -force
sudo rm -f ~/.bash_history
export HISTSIZE=0
```

**Output:** The script prints the gallery name, image definition, and version to reference in Partner Center.

**Cleanup:** After publishing, delete the temporary resources:
```bash
az group delete --name neo4j-ce-image-rg --yes --no-wait
```

> **Note:** Do NOT delete the resource group until the image has been successfully published in Partner Center. The gallery must remain accessible during the certification process.

#### Upload to Partner Center

1. Go to **Partner Center** > `neo4j-ce-vm` > `per-core-hour` plan > **Technical Configuration**
2. Click **+ Add VM Image**
3. Set version to `1.0.0`
4. Image type: **x64 Gen 2**
5. Under **Azure Compute Gallery**, select:
   - Gallery: `neo4jmarketplace`
   - Image: `neo4j-ce-vm`
   - Version: `1.0.0`

## Next Steps

### Immediate

1. **Create the `neo4j-ce-vm` Azure Virtual Machine offer** in Partner Center
   - Offer ID: `neo4j-ce-vm`
   - Offer alias: `Neo4j Community Edition VM`

2. **Create the `per-core-hour` plan** within the VM offer
   - Configure pricing at $0.04/core hour

3. **Fill in the VM offer listing details** (description, logos, links, etc.)

4. **Create and upload the CE VHD image:** `./makeVm.sh` (see "Creating the CE VHD" section above)

5. **Configure the VM offer Technical Configuration** (ports, properties, image — matching EE settings above)

### Before Publishing the Solution Template

6. **Update `marketplace/neo4j-ce/modules/vm.bicep`** to reference `neo4j-ce-vm` image instead of stock RHEL (see "Required Template Change" section above)

7. **Get a Customer Usage Attribution GUID** from Microsoft and update the placeholder `XXXXXXXX-XXXX-XXXX-XXXX-XXXXXXXXXXXX` in `marketplace/neo4j-ce/main.bicep`

8. **Generate the archive:** `cd marketplace/neo4j-ce && ./makeArchive.sh`

9. **Upload `archive.zip`** to the `neo4j-ce` offer's Technical Configuration in Partner Center

### Testing

10. **Test end-to-end** in Preview before going Live — Partner Center allows preview deployments before public listing
